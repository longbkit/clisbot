# Channel P0 — Live Test Scenarios

Status legend — a scenario is `PASS` only when every numbered assertion was
observed live in this session or the cited session, with the evidence on file.
`PARTIAL` = the chain fired but at least one assertion failed or was not
observed. `BLOCKED` = cannot run right now (reason named). `UNVERIFIED` =
runnable, not yet run. `NOT-IMPLEMENTED` = the feature does not exist yet.
Never mark `PASS` from static inspection: read-back must match what was sent.

Re-run rule: statuses rot. Before citing a `PASS`, re-run the scenario or say
which session produced it (date in the Status column).

## H. Provider matrix: channel plane is provider-agnostic (Slack only)

The channel plane consumes `agent_stream` events without knowing the provider —
the provider is chosen on the **route's `agent` target**, which
`resolveAgentSpec` (`control-plane.ts`) maps to the daemon `create_agent` config
(`provider`, `model`, `providerOptions`) + the environment's `cwd`. So "test a
provider" = point the Slack route's agent target at that provider and re-drive
the C-group chain; the plane's job is to relay whatever that provider's stream
emits. **One channel (Slack) is sufficient** — the provider variable is
orthogonal to the channel vertical; Telegram would only re-test the vertical,
not the provider.

Providers under test: `codex`, `claude`, `opencode`, `cursor`, `grok`, `pi`.
Built-in providers in the registry (`persisted-config.ts` `BUILTIN_PROVIDER_IDS`)
are `claude/codex/copilot/opencode/pi/omp`; `cursor` is an ACP agent
(`cursor-acp-agent.ts`), and `grok`/`trae`/`kimi`/`kiro` are ACP/custom-provider
agents (provider id + optional `command` override). The marker asks the agent
for an exact `PONG-<PROV>-…` reply so read-back matching is exact.

Per provider, the shared assertions are the C-group chain: inbound steer (A1
shape) → a real turn → relay posts the final answer into `$SLACK_TEST_CHANNEL`
→ `conversations-history`/`conversations-replies` read-back matches the marker;
plus the provider-specific deltas named per row. Watch the provider-specific
stream shapes the relay must survive: **coalesced `messageId` items** (all
providers — C8), **boundary markers** (Codex `---`, C8), **subagent
`provider_subagents` frames** (C9), and **`permission_requested`
`kind: "question"`** for AskUserQuestion (E5) — these arrive on the same
`agent_stream` path regardless of provider, but each provider emits them
differently.
