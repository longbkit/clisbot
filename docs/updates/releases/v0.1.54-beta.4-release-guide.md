# clisbot v0.1.54-beta.4 Release Guide

Use this guide when testing the `0.1.54-beta.4` beta from `0.1.53`,
`0.1.54-beta.1`, `0.1.54-beta.2`, or `0.1.54-beta.3`.

## What Changed

`0.1.54-beta.4` continues the `0.1.54` beta line after `0.1.54-beta.3`.

The main things to notice:

- A flexible runner backend layer: one shared `RunnerBackend` contract with
  `tmux` (default) and `acp` implementations. Nothing changes for existing
  tmux agents unless you opt in.
- A one-file provider catalog and a generated capability matrix, so per-CLI and
  per-backend behavior (steer, interrupt, resume, attach, native slash
  pass-through) is declared instead of assumed.
- The OpenCode provider, defaulting to the `acp` backend with validated
  `session/load` resume.
- `/steer` on ACP now works as interrupt-and-redirect when mid-turn steering is
  unsupported, with a truthful thread notice.
- A session event feed plus web view endpoints and a built-in demo page on the
  API channel.
- The default interactive runner startup window moves from `60` to `120`
  seconds for Codex, Claude, Gemini, and OpenCode.

## Update

```bash
npm install -g clisbot@0.1.54-beta.4
clisbot restart
clisbot status
```

Or use the beta dist-tag:

```bash
npm install -g clisbot@beta
clisbot restart
clisbot status
```

## Migration

Manual action: none.

There is no new schema migration in this beta. The new runner fields
(`backend`, `env`, `newSessionCommand`, `acp`) are optional; an unset `backend`
resolves to `tmux`, so existing behavior is unchanged until you opt in.

## What To Check After Restart

```bash
clisbot --version
clisbot status
```

Expected version: `0.1.54-beta.4`.

Runner validation:

- `clisbot agents list` should show `opencode` as an available CLI choice.
- Switching an existing Codex or Gemini agent to `acp` (one config line) should
  run with structured streaming, first-class `/stop`, and `session/load` resume
  across a restart where the provider advertises it.
- `/steer <msg>` on an ACP agent should interrupt the running turn, apply the
  message as the next prompt, and post a truthful notice.
- Existing tmux agents should behave exactly as before.

## Known Risks

- ACP is opt-in; the default backend stays `tmux`. Claude-over-ACP remains
  `not-recommended` until Anthropic's subscription/SDK billing split settles.
- `runner.env` values are stored in plain text in `clisbot.json`; keep the
  config private until credential-ref support lands.
- There is still no global runner pool or global concurrent runner-start limit;
  bursts across many conversations can still start many runner sessions.
