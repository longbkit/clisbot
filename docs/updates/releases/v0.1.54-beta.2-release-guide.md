# clisbot v0.1.54-beta.2 Release Guide

Use this guide when testing the `0.1.54-beta.2` beta from `0.1.53` or
`0.1.54-beta.1`.

## What Changed

`0.1.54-beta.2` continues the API channel hardening beta after
`0.1.54-beta.1`.

The main things to notice:

- The packaged API listener now uses Node's built-in HTTP server instead of
  `Bun.serve`.
- API bots installed from npm no longer require Bun just to run the listener.
- API ingress, HMAC verification, result polling, and result writeback keep the
  same API request/response contract.
- Runtime stop uses a bounded forced close path so an open API request does not
  leave the listener hanging during shutdown.
- Shared JSON file storage now waits longer under lock contention, which reduces
  transient `ELOCKED` failures when API result stores receive many concurrent
  writes.
- Global runner admission/backpressure for high-burst API traffic is still
  planned work, not implemented in this beta.

## Update

```bash
npm install -g clisbot@0.1.54-beta.2
clisbot restart
clisbot status
```

Or use the beta dist-tag:

```bash
npm install -g clisbot@beta
clisbot restart
clisbot status
```

## Migration

Manual action: none.

There is no new schema migration in this beta. Existing explicit API listener
configuration wins; otherwise the default listener port is `6868`.

## What To Check After Restart

```bash
clisbot --version
clisbot status
```

Expected version: `0.1.54-beta.2`.

For API channel validation:

- Starting the API listener from the npm-installed CLI should work under Node
  without Bun installed.
- Ingress should accept configured API events and return the expected result URL.
- Polling the event result should show progress/final output.
- `clisbot message send --channel api --reply-to <eventId>` should update the
  matching result record.
- If `actions.message.send` is configured, provider delivery should use the
  reply metadata from the target event.

## Known Risks

- There is still no global runner pool or global concurrent runner-start limit.
  Bursts across many API conversations can still start many runner sessions.
- API media/file delivery is not part of this beta.
- Live Chatwoot/Jira provider validation still depends on a configured provider
  sandbox; local automated coverage verifies the API channel contract and a
  packaged Node listener smoke.
