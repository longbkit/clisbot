# clisbot v0.1.54-beta.3 Release Guide

Use this guide when testing the `0.1.54-beta.3` beta from `0.1.53`,
`0.1.54-beta.1`, or `0.1.54-beta.2`.

## What Changed

`0.1.54-beta.3` continues the `0.1.54` beta line after `0.1.54-beta.2`.

The main things to notice:

- Runner resume failures now distinguish rejected or non-resumable native
  session ids from generic tmux startup failure.
- clisbot preserves stored session ids when automatic fresh-session rotation
  would risk losing the native conversation context.
- Codex state database startup failures, such as SQLite lock/open failures, now
  produce clearer operator recovery guidance.
- tmux session handshake recovery has more coverage around startup blockers,
  resume rejection, and prompt-submission truthfulness.
- Slack mrkdwn replies preserve nested list hierarchy better.
- The API channel hardening from `0.1.54-beta.1` and `0.1.54-beta.2` remains in
  this beta.

## Update

```bash
npm install -g clisbot@0.1.54-beta.3
clisbot restart
clisbot status
```

Or use the beta dist-tag:

```bash
npm install -g clisbot@beta
clisbot restart
clisbot status
```

## Migration

Manual action: none.

There is no new schema migration in this beta. Existing explicit API listener
configuration still wins; otherwise the default listener port remains `6868`.

## What To Check After Restart

```bash
clisbot --version
clisbot status
```

Expected version: `0.1.54-beta.3`.

Runner validation:

- A stale or rejected native resume id should fail with a clearer recovery
  message instead of a generic runner startup failure.
- Codex SQLite state database lock/open failures should be reported as Codex
  state failures with concrete cleanup guidance.
- `/new` remains the explicit operator action for intentionally starting a new
  runner conversation when the stored native session cannot be trusted.

Slack validation:

- Nested bullet or numbered lists should keep their hierarchy when rendered as
  Slack mrkdwn.

## Known Risks

- There is still no global runner pool or global concurrent runner-start limit.
  Bursts across many API conversations can still start many runner sessions.
- API media/file delivery is not part of this beta.
- Live Chatwoot/Jira provider validation still depends on a configured provider
  sandbox; local automated coverage verifies the API channel contract and a
  packaged Node listener smoke.
- Chat command `/resume <id>` is not a force-resume command for native runner
  ids; native resume remains managed by stored session id recovery.
