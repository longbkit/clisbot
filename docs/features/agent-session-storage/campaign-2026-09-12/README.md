Source: `benchmarks/2026-09-12-frozen.json` (started 04:07:52Z, ended 04:46:18Z,
`smoke:false` = full run). Environment: Node v22.23.2, Linux x64, AMD EPYC, 4 logical
CPUs, 8.3 GB RAM (cgroup 7.5 GB), overlayfs. **Integrity (independently verified):**
HEAD `3e4df80f4` + upstream `fa93c4290` identical in `sourceStart` and `sourceEnd`;
the fingerprint delta is only the untracked benchmark-harness scripts, the one test file
`projected-timeline-index.test.ts` (mtime 04:18, a test — not harness-imported),
`whole-daemon-steady-state.ts`, and this report. All four harness-imported production
modules (`file-agent-timeline-store`, `paged-journal`, `agent-storage`,
`projected-timeline-index`) have mtimes predating run start — **measured production
source is byte-stable across the run**. Do NOT claim fingerprint equality; claim
"measured source stable; fingerprint deltas = [documented files]".

**Against the README p95 targets (web/desktop production, SSD, local net, ready daemon):**

- click→last-page ≤1 s (empty cache/valid index): daemon-side cold p95 ack 340 ms @100k —
  **met at the daemon boundary** on this box (client+network not included).
- cached ≤200 ms: warm p95 ack 353 ms @100k — **not met on this environment** (4 vCPU,
  8 GB, overlayfs, not an SSD production host).
- scroll ≤300 ms: warm p95 353 ms — **not met on this environment** for the same reason.

These are **reported numbers, not claimed passes**: the unmet cached target is an
environment artifact, and the README states the targets are "unmeasured" initial goals.

performance bar is closed here or requires a production-SSD re-run. 10-writer write
amplification is high (563.4 MiB physical / 2.67 MiB logical ≈ 211×, 193,371 fsyncs
for 10,000 rows); the derived-node allocation probe
(`derived-allocation-frozen.json`: 15,919 derived docs / 67.2 MiB allocated @1k rows)
attributes part of it before a final AC7 write-amplification claim.

### RAM / I/O / durability — AC6 whole-daemon steady state (verified by coordinator)

Source: `/tmp/whole-daemon-steady-state.json` (run 05:21:23Z–05:29:21Z) +
`benchmarks/2026-09-12-frozen.md` §"Whole-daemon steady state". Real in-process daemon,
200 sessions × 204 rows through the shared 128-owner store, 6 cycles of open projected
tail + one scroll page + directory lookup per session via the daemon's real
`agentManager.fetchProjectedTimelineForRead`. **Verified from JSON:**

- `ownersBounded: true` — 128/128 resident owners every cycle, no growth;
- post-GC RSS peak (last half) 336.6 MiB; **0.5 MiB growth first→last cycle**
  (`rssGrowthFirstToLastCycleBytes: 524,288`) — steady state reached;
- post-GC heap peak (last half) 158.1 MiB, flat;
- event-loop lag p95 16.9 → 16.1 ms (no growth);
- `queueGrewUnboundedly: false` — pending journal capped at 16 MiB / 1,024 ops
  (pending-event-budget tests);
- **restart proof:** a fresh daemon over the same home lists all 200 sessions and reads
  the last session's tail to `endSeq=204` with agents closed.

Companion durability artifacts on the same frozen source (all verified):
[derived-allocation probe](../benchmarks/2026-09-12-derived-allocation-frozen.json)
(15,919 derived docs / 67.2 MiB allocated @1k rows), [AC9 rollback-check](../benchmarks/2026-09-12-rollback.json),
and ENOSPC/SIGKILL re-runs (storage-review 12/12, `/tmp/storage-lane-r4-review.log`).
Crash evidence is process-kill only; power-loss and Windows are not claimed.

Boundary: this is the whole-daemon store/manager/server-scaffolding RAM under a fixed
sequential load — **not** app/provider memory, not a production packaged daemon. It
closes the "whole-daemon steady state at fixed budget" and "non-growing queue" items for
AC6 at this boundary; the app-side and provider-side retention evidence remain owned by
the ui lane.
