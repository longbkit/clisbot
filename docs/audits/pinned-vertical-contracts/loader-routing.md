# The aliased `openclaw/plugin-sdk/*` seam + routing lifetime

The Slack vertical imports **96 distinct** `openclaw/plugin-sdk/*` subpaths (matrix: `packages/hub/seam-matrix/slack.json` — 1 bound `channel-inbound` with the 4 host exports `dispatchChannelInboundReply` / `runChannelInboundEvent` / `runPreparedInboundReply` / `dispatchReplyFromConfigWithSettledDispatcher`; 95 passthrough; 0 unsupported; conformance complete). Telegram's bundled closure imports zero aliased subpaths (see `telegram-monitor.md`), so the matrix only covers Slack at P0.

Three of the 96 are invisible to a naive `import … from "…"` scan — a bare side-effect import (`channel-plugin-common`, `slack/dist/runtime-api-CEmqYxR-.js:7`) and two const-mediated dynamic imports (`extension-shared`, `target-resolver-runtime`, `slack/dist/channel-BjlsaGHn.js:513-516` via `createLazyRuntimeModule(() => import(CONST_MODULE_ID))`); the matrix generator scans every quoted specifier as a second pass.

Several aliased subpaths load **lazily at drive time** (the monitor module; the two const-mediated ones) — i.e. after `endChannelLoad` — and `entry.setChannelRuntime` (post-load) itself imports a runtime-setter chunk whose chain reaches `openclaw/plugin-sdk/runtime-store`. The resolve hook therefore routes aliased specifiers for the **process lifetime**, keyed by `parentURL` prefix (each loaded channel's install roots → its mainDir/channelDir/seam info), not only during an active load; unclassified specifiers fail closed with a typed throw. Passthrough subpaths resolve into **that channel's** main package dir (per-channel instance isolation, §4.1).

The bound subpath is served as a merged module: `export *` from the pinned main's real subpath (the pure normalizers stay OpenClaw's) + the seam names re-exported from the in-repo host module (`hosts/channel-inbound.ts`) — the named re-export wins over the star.

**The seam loads at drive time, not load time (verified against the pinned dist, 2026-08-26).** The bound subpath's importers are `slack/dist/pipeline.runtime-rpVpay59.js` (static import of 14 subpath exports incl. `dispatchChannelInboundReply`) and `slack/dist/provider-C1-DFSpw.js` (debouncer exports) — and `provider-C1-DFSpw.js` itself is pulled only by a `import("./pipeline.runtime-rpVpay59.js")`-shaped lazy chain reached from the monitor, i.e. after `startAccount` is driven. A real pinned-Slack load-trace (the `vertical-contract.native.ts` gate, `npm run test:contract:native`) records **2294 modules, zero `__hub__` seam URLs**: the entry + plugin chunk import cleanly through the full 96-subpath matrix at load time; the seam URL first appears when the inbound pipeline loads at drive time. Consequences: (a) a load-time absence of the seam URL in `loadedModules` is CORRECT, not a miss — the loader's matrix/allowlist assertions already failed closed on any unclassified subpath, so a completed load is the load-time import contract; (b) the lifetime `parentURL` routing (D5) is load-bearing for the seam itself, not just "other lazy subpaths"; (c) drive-time seam dispatch against real supply is the live E2E's acceptance case, not a unit test's.
